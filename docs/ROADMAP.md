# Roadmap

Планы релизов после `0.1`. Текущая работа — в [TODO.md](TODO.md), идеи без срока — в [BACKLOG.md](BACKLOG.md).
Правила: каждая фича — ветка `feature/<название>` → `dev`; релиз — слияние `dev` → `master`; номер минора задаёт `version.txt`.
Размер: S — до дня, M — 2–3 дня, L — неделя.

## 0.1.x — патчи
Исправления по итогам реального использования: тексты, названия, обязательность отдельных ингредиентов (миграцией), баги.

## 0.2 — Обратная связь и порядок
Цель: видеть, как бот используют, и закрыть обязательное по данным пользователей. Почти без новой логики подбора.
- [x] **Админ-статистика** `/admin` (скрытая команда, по образцу poi-bot): аудитория (всего, новые и активные за 1/7/30 дней), число отмеченных ингредиентов, доля пустой выдачи, популярные ингредиенты и коктейли. Таблицы `user_activity_day`, `cocktail_view`. (M)
- [x] **`/deleteme`**: выгрузка данных JSON-файлом и удаление (пользователь, профиль, ингредиенты, состояния), в два шага с подтверждением. (M)
- [x] **Новые товары в справочнике**: по умолчанию `is_essential = FALSE` и разметка при импорте, чтобы после обновления данных безалкогольные товары не становились обязательными (сейчас значение по умолчанию TRUE). Описать процесс обновления справочника. (S)
- [x] **`/settings`**: возврат к автоопределению языка по Telegram. (S)

## 0.3 — Безалкогольные и любимое
Цель: расширить аудиторию и дать причину возвращаться.
- [x] **Безалкогольные коктейли** (41 в ru): отдельный раздел в `/cocktails` без подбора по ингредиентам, в карточке всё необязательное помечено •, блок «нужно купить». (M)
- [x] **Избранное** ⭐ и «уже готовил» ✅ в карточке; раздел «Избранное» в `/cocktails`; таблица `user_cocktail`. (M)
- [x] **«🎲 Удиви меня»**: случайный коктейль из раздела «можно приготовить». (S)

## 0.4 — Умный подбор
Цель: меньше ложных «не хватает», точнее выдача.
- [x] **Замены товаров**: таблица `goods_substitute`, подбор, «что купить», карточка («заменено: …») и статистика учитывают замены. Пока одна пара: «Драй Оранж» / «Трипл сек». (L)
- [ ] Остальные пары замен: ручной подбор по каталогу, добавляются миграциями (`docs/CATALOG.md`).
- [x] **Режим «отмечать и необязательные»**: в `/ingredients` категории `JUICE`, `MIXER`, `FRUIT`, `PANTRY` (миграция `catalog/9`); строгий подбор по ним включается в `/settings` (`UserSettings.strictMatching`). (M)
- [x] **Фильтры по тегам коктейля** (`CocktailTag`, кнопка «🔎 Фильтр» в `/cocktails`): 16 тегов в 4 группах, выбор хранится в настройках. (M)
- [x] **Fallback локали**: коктейли, которых нет на выбранном языке, показываем на английском с пометкой. (S)

## 0.5 — Языки
Цель: полноценная локализация на все 8 языков.
- [x] Перевод интерфейса (кнопки, подсказки, `/start`, `/help`, 15 шаблонов, ~96 ключей) на ua, de, es, fr, it; `uk` — английский интерфейс. (L)
- [x] Язык интерфейса по выбранному флагу; тест консистентности для всех языков (`MessagesConsistencyTest`). (S)
- [x] Меню команд (`SetMyCommands`) на всех языках. (S)

## 0.6 — Кухня
Цель: удобство при реальном приготовлении.
- **Список покупок**: из «что купить» и из выбранных коктейлей, отметка купленного. (M)
- **Пересчёт порций** в карточке (×1/×2/×4). (S)
- **Гаджеты**: отметка инвентаря и пометка в карточке, чего не хватает. (M)
- **Фото коктейлей**, если появятся в данных. (зависит от данных)

## 0.7 — Мониторинг
Цель: техническая наблюдаемость, когда основное будет готово и сервер выдержит нагрузку.
- **Метрики Micrometer** через actuator (`/actuator/prometheus`): апдейты, время ответа, ошибки, длительность подбора. Нужны Prometheus и Grafana; перед началом оценить ресурсы сервера (возможен облегчённый вариант). (M)
- Хранение логов в Loki/Grafana вместо файла на сервере (из бэклога), если мониторинг будет поднят. (M)

## Постоянно
- Обновление зависимостей (Spring Boot, Kotlin, telegrambots) раз в квартал.
- Резервные копии БД (`docs/DEPLOY.md`, раздел 6).
- Ревью `is_essential` по обратной связи пользователей.
